Submission and review提交与审核

Submit and review results in a private GitHub pull request (PR). Only the approved summary appears on the community leaderboard.通过 GitHub 私有拉取请求（PR）提交和审核结果，社区榜单只公开审核通过的摘要。

Preparation preview — submissions are not open. Do not upload evidence or create a PR yet.当前为准备阶段预览，尚未开放提交。请勿上传证据或创建 PR。

Participant submission参评者提交

  1. Prepare two files准备两个文件

    Complete all 200 tasks in Async mode, with three repetitions per task. Use the packaging command in the participant template to create evidence.zip and submission.json from the scores, original traces, manifest, audit and result metadata. Packaging runs locally and does not upload files.完成 200 个任务、每个任务 3 次重复的 Async 测评。按照投稿模板中的打包命令，将分数、原始轨迹、运行清单、审计记录和结果信息生成 evidence.zip 与 submission.json。打包在本地完成，不会上传文件。

  2. Create a private repository建立私有仓库

    Use the template above and select Private. Install the review App on only this repository and invite @pope8zdt as a collaborator. No secrets or Actions workflows are needed.使用上方模板入口，选择 Private。审核 App 只授权这个仓库，并邀请 @pope8zdt 为协作者。不需要配置密钥或 Actions 工作流。

  3. Open a private PR发起私有 PR

    On a new branch, place both files at the repository root. Open a non-draft PR to main in that same private repository. The review service finds it automatically; no separate file transfer is needed. Do not upload evidence to the public project or template repository.新建分支，把两个文件一起放在仓库根目录，再向同一个私有仓库的 main 分支发起非草稿 PR。审核服务会自动发现，无需另外私发文件。不要向公开项目或模板仓库上传证据。

  4. Read the receipt on your PR在 PR 中查看回执

    Validation results, review feedback and rejection reasons stay on the private PR. Push any corrections to the same branch; every new commit needs fresh validation and approval.校验结果、审核意见和拒绝原因都在该私有 PR 中查看。需要修改时，推送到同一分支；每个新版本都要重新校验和批准。

Maintainer review维护者审核

  1. Find the submission查看投稿

    Accept the collaborator invitation, then open the participant’s private repository → Pull requests. Review submissions there, not in the central review repository. Read the validation receipt and inspect the original evidence; automated checks do not replace manual verification that the run is genuine.先接受协作者邀请，再进入参评者的私有仓库 → Pull requests。投稿在这里审核，不是在中央审核仓库。先查看校验回执，再检查原始证据；自动校验不能代替对运行真实性的人工核验。

  2. Approve通过

    Once the current commit passes validation and you have verified the evidence, select Files changed → Review changes → Approve, then click Submit review. No merge or local command is needed. A merge alone is not approval, and reviewers cannot approve their own submissions.确认当前版本校验通过、证据可信后，选择 Files changed → Review changes → Approve，再点击 Submit review。无需合并 PR，也不需要本地执行命令。单纯合并不等于审核通过，维护者不能批准自己的投稿。

  3. Request changes or reject要求修改或拒绝

    Select Request changes, explain the problem and click Submit review. Leave the PR open for corrections. To reject it, also select Close pull request without merging. The participant reads the reason on the private PR.选择 Request changes，写明问题并点击 Submit review。要求修改时保留 PR，等待更新；拒绝时再点击 Close pull request，不合并。参评者直接在私有 PR 查看原因。

  4. Withdraw an approved result撤回已通过的结果

    Dismiss the approval or close an unmerged PR. The next successful sync removes its community entry. A new commit always requires fresh validation and approval.撤销批准，或关闭尚未合并的 PR。下一次成功同步会移除社区条目。提交新版本后，始终需要重新校验和批准。

Confirm community sync确认社区榜单已同步

Approved summaries sync every four hours. GitHub scheduling and page caching can add delays.审核通过的摘要每四小时同步一次，GitHub 调度和页面缓存可能额外延迟。

  1. Check the workflow检查同步任务

    Open the private review workflow and check that a run after the approval succeeded. This page is for maintainers; participants use their private PR receipt.打开私有审核工作流，确认批准之后的一次运行成功。该页面仅供维护者查看；参评者查看自己私有 PR 中的回执即可。

  2. Check the community entry核对社区条目

    Open Leaderboard → Community results and match the model, code revision and scores. A successful workflow alone does not mean a particular submission was published.打开榜单 → 社区结果，核对模型、代码版本和成绩是否出现。任务运行成功，不等于某一条投稿已经上榜，仍需检查对应条目。

What becomes public哪些内容会公开

Only the approved summary: agent and model names, organization, code revision, scores, coverage, submitter and reviewer usernames, review time and scoring-policy version.仅公开审核通过的摘要：智能体与模型名称、机构、代码版本、分数、覆盖范围、提交者及审核者用户名、审核时间和评分策略版本。

Original evidence, private repository links and rejection reasons stay private, including after approval. Access is limited to the owner, invited collaborators and the authorized review service. Keep your repository private and never include credentials in evidence. GitHub may send notifications according to your account settings.原始证据、私有仓库链接和拒绝原因在批准后也不公开，仅仓库所有者、受邀协作者及已授权审核服务可访问。请始终保持仓库私有，证据中不得包含密钥。GitHub 可能按你的账号设置发送通知。

Community results are stored and displayed separately. They never modify the paper leaderboard.社区结果独立存储与展示，不修改论文榜单。
