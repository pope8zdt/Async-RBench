Submission and review提交与审核

Use a private PR for the evidence and review. Only an approved summary appears on the community leaderboard.证据与审核留在私有 PR 中，只有审核通过的摘要出现在社区榜单。

Preparation preview — submissions are not open. Do not upload evidence or create a PR yet.当前为准备阶段预览，尚未开放提交。请勿上传证据或创建 PR。

For participants参评者怎么提交

  1. Prepare the result files准备结果文件

    Complete all 200 tasks in Async mode, with three repetitions per task. Package the scores, original traces, manifest, audit and result metadata into evidence.zip. The companion submission.json records the archive digest and consent to publish the approved summary. The local packaging command is in the participant template. Packaging does not run an evaluation or upload files.完成全部 200 个任务的 Async 测评，每个任务重复三次。将分数、原始轨迹、运行清单、审计记录和结果信息打包为 evidence.zip。配套的 submission.json 记录证据包摘要及公开已审核摘要的同意声明。投稿模板提供本地打包命令，不会重新测评或上传文件。

  2. Set up your private repository建立自己的私有仓库

    Once submissions are open, create a Private repository from the participant template. Install the review App on that repository only and invite @pope8zdt as a collaborator. Do not add secrets or Actions workflows. Never upload evidence to the public benchmark or template repository.提交入口开放后，从投稿模板创建 Private 仓库。审核 App 仅授权该仓库，并邀请 @pope8zdt 为协作者。无需添加密钥或 Actions 工作流，切勿把证据上传到公开项目或模板仓库。

  3. Open a PR in that repository在同一私有仓库发起 PR

    On a new branch, place submission.json and evidence.zip together at the repository root. Open a non-draft PR from that branch to main. The review service discovers it automatically; you do not need to send files privately or open a public issue.新建分支，将 submission.json 和 evidence.zip 一起放在仓库根目录，再向该仓库的 main 分支发起非草稿 PR。审核服务会自动发现，无需另外私发文件或创建公开 Issue。

  4. Read the private receipt查看私有回执

    Validation results and review feedback appear on the PR. Push corrections to the same branch; each new commit requires fresh checks and approval. Approved summaries are synchronized every four hours, subject to GitHub scheduling and availability.校验结果与审核意见显示在该 PR 中。修改后推送到同一分支，每个新版本都需重新校验和批准。摘要每四小时定时同步一次，实际时间受 GitHub 调度与服务可用性影响。

For the maintainer维护者怎么审核

Read the validation receipt and inspect the original evidence in the participant's private repository. Checks cover identity, file digests, protocol version and complete coverage; they do not prove that a run was conducted honestly. Review the evidence before approving.先查看校验回执，再检查参评者私有仓库中的原始证据。自动校验涵盖身份、文件摘要、协议版本与完整覆盖，但不能独立证明运行真实可信，批准前仍需人工核验。

To accept, use GitHub's Approve on the validated commit. The service then synchronizes the summary automatically. A merge is neither required nor sufficient for approval. Reviewers cannot approve their own submissions.通过时，对已校验的提交版本使用 GitHub 的 Approve。服务随后自动同步摘要，不需要本地执行命令。无需合并 PR，单纯合并也不等于审核通过；维护者不能批准自己的提交。

To request corrections, use Request changes and explain what is missing. To reject, leave the reason in that review and close the PR without merging. The participant reads the reason and receipt on the private PR.需要修改时，使用 Request changes 写明问题；拒绝时，在该审核中说明原因，再关闭 PR、不合并。参评者直接在私有 PR 查看原因和回执。

To withdraw an approved result, dismiss the approval or close the unmerged PR. The next successful sync removes its community row; cached pages may briefly retain it. New commits always require a new review.需要撤榜时，撤销批准，或关闭尚未合并的 PR。下一次成功同步会移除社区条目，缓存页面可能短暂保留旧结果。更新提交后始终需要重新审核。

What becomes public哪些内容会公开

Only the approved summary: agent and model names, organization, code revision, scores, coverage, submitter and reviewer usernames, review time and scoring-policy version.仅公开审核通过的摘要：智能体与模型名称、机构、代码版本、分数、覆盖范围、提交者及审核者用户名、审核时间和评分策略版本。

Original evidence, private repository links and rejection reasons stay private, including after approval. Access is limited to the owner, invited collaborators and the authorized review service. Keep your repository private and never include credentials in evidence. GitHub may send notifications according to your account settings.原始证据、私有仓库链接和拒绝原因在批准后也不公开，仅仓库所有者、受邀协作者及已授权审核服务可访问。请始终保持仓库私有，证据中不得包含密钥。GitHub 可能按你的账号设置发送通知。

Community results are stored and displayed separately. They never modify the paper leaderboard.社区结果独立存储与展示，不修改论文榜单。
