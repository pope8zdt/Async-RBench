中断后怎样继续？How do I resume?

保持计划、judge 和模型配置不变，在同一 run-manifest 命令后加 --resume。框架跳过已完成且绑定匹配的运行。Keep the manifest, judge and model profile unchanged and add --resume to the same run-manifest command. Completed, binding-matched runs are skipped.

汇总与审计Aggregate and audit

async-rbench-eval aggregate --root runs/first --manifest first-manifest.json --output aggregate.json
async-rbench-eval audit-run --root runs/first --judge-root "<judge-root>" --output first-audit.json

运行版汇总在 development_summary 中，原始指标范围为 [0,1]；展示为 DRS 或百分比时乘 100。少量试跑覆盖不足时，总分可能为 null，应看逐次结果和覆盖报告，不能把 null 当作零。Runtime aggregates are under development_summary on [0,1]; multiply by 100 for DRS or percentage display. Partial trials may have null headline metrics because coverage is incomplete. Read episode results and coverage; do not treat null as zero.

DRS 和成功率各测什么？What do DRS and success measure?

DRS 检查新结果之后的必要修改、有效工作保留、禁止行为和重新验证，并结合事件最终结果。成功率只统计完整任务目标全部通过的运行；两者分别报告。DRS checks required changes, retained work, forbidden effects and verification after a new result, together with the event outcome. Success counts runs that pass all task goals. They are reported separately.

当前汇总器的 async_task_success 要求同时有 Async 和 Batched 记录；即使跑完 200 个 Async 任务，它也会为 null。只测 Async 时读取上列 observed 字段，不必为此添加基线。The current aggregator requires paired Async and Batched records for async_task_success. It remains null even after all 200 Async tasks. For Async-only evaluation, use the observed field above; adding a baseline is not required.

汇报前检查 aggregate.json 的 audit.manifest_completion_rate、audit.missing_episode_ids 和场景覆盖；只覆盖部分任务的 observed 值不应当作完整成绩。Before reporting, inspect audit.manifest_completion_rate, audit.missing_episode_ids and scenario coverage in aggregate.json. An observed value from partial coverage is not a complete benchmark result.

汇总与审计分别检查什么？What do aggregation and audit check?

上面的 aggregate 命令显式绑定 first-manifest.json，检查计划覆盖。audit-run 检查契约、产物和版本；它只自动寻找 runs/manifest.json，不绑定本例的 first-manifest.json，因此通常显示 manifest_complete: null。计划是否完整，以显式绑定 manifest 的汇总报告为准；不要用无绑定的审计结果替代覆盖检查。The aggregate command explicitly binds first-manifest.json and checks plan coverage. audit-run checks contracts, artifacts and versions, but only auto-discovers runs/manifest.json, not this example’s first-manifest.json. Its manifest_complete is therefore normally null. Use the manifest-bound aggregate report for coverage, not an unbound audit.

可选对照：添加 Batched，与 Async 配对Optional baseline: pair Batched with Async

Batched 只是实验对照，不是主要模式。内部键 linear 表示 Batched：子代理仍并行执行，只是等待结果汇齐后再呈现。200 任务 × 2 模式 × 3 次 = 1,200 次运行 / 模型。Batched is a comparison baseline, not the main mode. Its internal key linear still runs children concurrently, but holds results until the required workstreams finish. 200 tasks × 2 modes × 3 repetitions = 1,200 runs / model.

async-rbench-eval make-manifest --output paired-200-manifest.json --execution-modes linear async --repetitions 3 --guidance incentive --seed 2026 --model YOUR_MODEL_ID --judge-root "<judge-root>"
async-rbench-eval run-manifest --manifest paired-200-manifest.json --output runs/paired-200 --profile reference_scaffold_api --runtime-mode api_only --config "<profile.yaml>" --judge-root "<judge-root>"
