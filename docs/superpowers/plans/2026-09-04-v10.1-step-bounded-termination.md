# Async-RBench v10.1.0 Step-Bounded Termination Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace v10.0 token-pool admission and guarded completion with a fixed-step, independently scored v10.1.0 execution contract.

**Architecture:** One actual-usage ledger records token diagnostics and provides only a 20M emergency fuse. Main and child loops stop by fixed model-response steps or voluntary stop; `finish` records closure facts but never coaches or refuses the model, while the unchanged private verifier and dynamic scorer decide success.

**Tech Stack:** Python 3.11+, asyncio, dataclasses, PyYAML, pytest; no new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-09-04-v10.1-step-bounded-termination-design.md`

## Global Constraints

- Official limits are exactly `max_main_steps=100`, `max_child_steps=40`, and `emergency_total_token_cap=20000000`.
- Linear and Async share the same step, child-spawn, concurrency, timeout, output-token, and emergency-safety limits.
- Token estimation and token reservations never decide whether a normal model call starts.
- `finish` is immediately terminal and never returns benchmark closure advice.
- Early participant stop is scored; only `resource_safety_abort` and existing infrastructure failures are unscored.
- Cases, event schedules, private verifiers, and running v10.0 artifacts are untouched.
- Every behavior change follows a red-green test cycle.
